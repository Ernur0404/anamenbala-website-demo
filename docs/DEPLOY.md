# Запуск магазина на сервере

Инструкция для установки «Ана мен бала» на собственный сервер (VPS) в Казахстане.
Всё работает в Docker: сайт и админка, база PostgreSQL 18, Caddy (HTTPS-сертификат выпускается
сам) и служебный контейнер с фоновыми задачами и резервными копиями.

```
Интернет ─► Caddy (80/443, HTTPS) ─► app (Next.js, порт 3000 внутри) ─► db (PostgreSQL 18)
                   └─ /uploads/* — фото напрямую с диска         cron ─► бэкапы, задачи
```

## 1. Что понадобится

- **VPS** с Ubuntu 24.04 LTS: от 2 vCPU, 4 ГБ памяти, 40 ГБ SSD (фото и бэкапы занимают место —
  лучше 60–80 ГБ). Подойдёт любой хостинг в Казахстане (PS.kz, Hoster.kz, QazCloud и др.).
- **Домен** (например, `anamenbala.kz`) с доступом к DNS-настройкам.
- Доступ к серверу по SSH.

## 2. DNS

У регистратора домена создайте записи:

| Тип | Имя   | Значение       |
|-----|-------|----------------|
| A   | `@`   | IP сервера     |
| A   | `www` | IP сервера     |

Записи начинают работать через 5–60 минут. Проверка: `ping anamenbala.kz` показывает IP сервера.

## 3. Подготовка сервера

```bash
# обновления и брандмауэр: открыты только SSH и веб
sudo apt update && sudo apt -y upgrade
sudo apt -y install git ufw unattended-upgrades
sudo ufw allow OpenSSH && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw allow 443/udp
sudo ufw --force enable

# Docker (официальный установщик)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # затем выйдите из SSH и зайдите снова
```

Порт базы данных наружу не открывается — она доступна только контейнерам.

## 4. Код и настройки

```bash
sudo mkdir -p /opt/ana-men-bala && sudo chown $USER /opt/ana-men-bala
git clone <адрес репозитория> /opt/ana-men-bala      # или распакуйте архив проекта в эту папку
cd /opt/ana-men-bala/deploy
cp .env.example .env
```

Сгенерируйте секреты и впишите их в `deploy/.env` (`nano .env`):

```bash
openssl rand -hex 24      # → POSTGRES_PASSWORD
openssl rand -base64 32   # → ENCRYPTION_KEY
openssl rand -hex 32      # → CRON_SECRET
```

Заполните `DOMAIN`, `ACME_EMAIL`, `APP_URL` (с `https://`).

> **Сохраните `ENCRYPTION_KEY` отдельно** (например, в менеджере паролей). Им зашифрован токен
> Telegram-бота; при восстановлении на новом сервере нужен тот же ключ.

## 5. Первый запуск

```bash
cd /opt/ana-men-bala/deploy
docker compose up -d --build          # первая сборка — 5–10 минут
docker compose ps                     # app — healthy, caddy и cron — running
```

При каждом запуске сначала автоматически применяются миграции базы (сервис `migrate`).

Начальное наполнение (категории и подкатегории как в макете, характеристики и фильтры, способы
доставки и оплаты, страницы, FAQ, настройки по умолчанию):

```bash
docker compose run --rm tools npm run db:seed
```

Демо-каталог для показа (товары со стоковыми фото, демо-заказы для графиков) — по желанию,
удаляется одной кнопкой в «Настройки → Демо-данные»:

```bash
docker compose run --rm tools npm run db:demo
```

Учётная запись владельца (временный пароль покажется один раз):

```bash
docker compose run --rm tools npm run create-owner -- owner@example.kz "Имя Фамилия"
```

Откройте `https://ваш-домен/admin`, войдите и сразу:

1. Меню в правом верхнем углу → «Мой профиль» → смените пароль и включите двухфакторную защиту.
2. «Настройки» → контакты, реквизиты Kaspi в способе оплаты, Telegram-бот, SEO.
3. Перед открытием магазина удалите демо-данные («Настройки → Демо-данные»).

Менеджеров добавляет владелец в «Настройки → Сотрудники».

## 6. Обновление

```bash
cd /opt/ana-men-bala
git pull
cd deploy && docker compose up -d --build
```

Миграции применяются автоматически. Перед крупным обновлением сделайте копию вручную (ниже).

## 7. Резервные копии

Контейнер `cron` каждую ночь (02:30) сохраняет:

- **базу** — `deploy/backups/daily/db_ГГГГ-ММ-ДД_ЧЧММ.dump`;
- **фото и видео** — снимок `deploy/backups/uploads/ГГГГ-ММ-ДД_ЧЧММ/` (неизменённые файлы не
  копируются повторно, а ссылаются на прошлый снимок — место не тратится).

Хранится 14 ежедневных и 8 еженедельных копий (по воскресеньям, папка `weekly`) — меняется в
`.env` (`BACKUP_KEEP_DAILY`, `BACKUP_KEEP_WEEKLY`). Каждый понедельник последняя копия
автоматически проверяется: разворачивается во временную базу, считаются товары и заказы.

```bash
docker compose exec cron /scripts/backup.sh           # копия прямо сейчас
docker compose exec cron /scripts/restore-check.sh    # проверить последнюю копию
docker compose logs cron | grep -E "backup|restore"   # журнал копий и проверок
ls -lh backups/daily
```

**Копия вне сервера** (обязательно хотя бы раз в неделю — если сервер пропадёт целиком):

```bash
# с вашего компьютера
scp -r user@сервер:/opt/ana-men-bala/deploy/backups ./ana-men-bala-backups
```

Или настройте `rclone` на сервере для выгрузки `deploy/backups` в облачное хранилище по расписанию
(`crontab -e` на сервере: `0 4 * * * rclone sync /opt/ana-men-bala/deploy/backups remote:anamenbala`).

## 8. Восстановление

```bash
cd /opt/ana-men-bala/deploy
ls backups/daily backups/weekly
./restore.sh backups/daily/db_2026-10-01_0230.dump              # только база
./restore.sh backups/daily/db_2026-10-01_0230.dump --uploads    # база и фото того же дня
```

Скрипт спросит подтверждение и выполнит по шагам:

1. страховочная копия текущей базы (`backups/safety/`) — если ошиблись копией, можно вернуться;
2. проверка выбранной копии во временной базе — повреждённая копия не затрёт рабочие данные;
3. остановка сайта → восстановление → миграции → запуск и проверка, что сайт отвечает.

**Перенос на новый сервер:** выполните шаги 3–5 (тот же `ENCRYPTION_KEY`!), скопируйте папку
`backups` в `deploy/` нового сервера и запустите `./restore.sh … --uploads`.

## 9. Диагностика

```bash
docker compose ps                    # состояние сервисов
docker compose logs -f app           # журнал сайта
docker compose logs -f cron          # фоновые задачи и бэкапы
docker compose restart app           # перезапуск сайта
curl https://ваш-домен/api/health    # {"ok":true} — сайт и база работают
df -h                                # свободное место
```

Фоновые задачи (контейнер `cron`): каждую минуту — отправка уведомлений и повтор неудачных,
каждые 5 минут — начало и конец акций (пересчёт цен), ночью — очистка устаревших сессий,
корзин и неиспользуемых фото. Снаружи адреса `/api/cron/*` закрыты.

## 10. Почта (по желанию)

Письма покупателям (подтверждение заказа, смена статуса) отправляются, если указан `SMTP_URL`:

```
SMTP_URL=smtps://shop%40anamenbala.kz:пароль@smtp.mail.ru:465
MAIL_FROM="Ана мен бала <shop@anamenbala.kz>"
```

`@` в логине записывается как `%40`. После изменения: `docker compose up -d app`.
Без SMTP магазин работает полностью, просто письма не уходят (уведомления в Telegram работают).

## 11. Безопасность

- Пароли сотрудников хранятся в виде хэшей (argon2id), вход защищён ограничением попыток,
  для сотрудников есть двухфакторная защита (приложение-аутентификатор).
- Сайт отдаётся только по HTTPS (HSTS), заголовки защиты и Content-Security-Policy включены.
- Секреты — только в `deploy/.env` (права `chmod 600 .env`), в репозиторий он не попадает.
- База и фото хранятся на вашем сервере в Казахстане.
- Регулярно: `sudo apt update && sudo apt -y upgrade` (или автоматически — `unattended-upgrades`).

## 12. Хранилище файлов

Фото и видео хранятся на диске сервера (Docker-том `ana-men-bala-uploads`) и попадают в
ежедневные бэкапы. Код рассчитан на подключение S3-совместимого хранилища (интерфейс
`Storage` в `src/server/media/storage.ts`), но сам драйвер S3 пока не подключён — для
одного магазина на VPS это не требуется.
